# Публикация путеводителя на GitHub Pages

Инструкция для проекта `E:\japan-travel`. Проверена по документации GitHub 16 ноября 2026 года. Публикацию выполняет пользователь.

Проект уже содержит готовые HTML-страницы и локальные фотографии. Для сайта не нужны платный сервер, домен, установка Node.js на GitHub или собственный сценарий сборки GitHub Actions. Публикуем готовые файлы из основной ветки.

## 1. Подготовить аккаунт и GitHub Desktop

1. Зарегистрируйся или войди на [GitHub](https://github.com/). Подтверди адрес электронной почты, если ещё не подтвердил.
2. Установи [GitHub Desktop для Windows](https://desktop.github.com/).
3. Открой приложение, нажми **Sign in to GitHub.com** и заверши вход в браузере.
4. Если приложение попросит имя и email для Git, укажи данные, которые будут использоваться для подписей сохранений.

Для бесплатного GitHub Pages на GitHub Free используем **публичный репозиторий**. Файлы проекта и сайт будут доступны другим людям. Приватный репозиторий сам по себе не делает Pages закрытым. [Доступность и видимость GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site).

## 2. Подключить существующую папку

1. В GitHub Desktop выбери **File → Add local repository…**.
2. Нажми **Choose…** и укажи `E:\japan-travel`.
3. Если приложение сообщает, что папка ещё не является Git-репозиторием, нажми ссылку **create a repository here instead**.
4. Проверь имя `japan-travel` и итоговый путь `E:\japan-travel`. При ручном заполнении окна создания поле **Name** должно быть `japan-travel`, а **Local path** — `E:\`, поскольку приложение добавляет папку с именем репозитория к выбранному пути. Не создавай вложенную папку `E:\japan-travel\japan-travel`.
5. Оставь **Git ignore** и **License** в значении **None**. Дополнительный README для публикации не нужен.
6. Нажми **Create repository**. Если снова показано окно добавления, нажми **Add repository**.
7. Открой **Repository → Show in Explorer** и проверь, что внутри видны `index.html`, `days`, `assets`, `tools` и документы проекта.

В папке уже есть пустой файл `.nojekyll`: он отключает обработку Jekyll и позволяет публиковать готовые статические файлы. Не переименовывай его в `.nojekyll.txt`. [О создании репозиториев](https://docs.github.com/en/desktop/overview/creating-your-first-repository-using-github-desktop), [о добавлении локальной папки](https://docs.github.com/en/desktop/adding-and-cloning-repositories/adding-a-repository-from-your-local-computer-to-github-desktop?platform=windows).

## 3. Первое сохранение и загрузка на GitHub

1. Во вкладке **Changes** проверь список файлов. Если есть несохранённые изменения, оставь нужные файлы отмеченными, в поле **Summary** напиши `Initial Japan travel guide` и нажми **Commit to main**. Если ветка называется иначе, кнопка покажет её имя. Если изменений нет и в **History** уже есть **Initial commit**, этот шаг выполнен.
2. Нажми **Publish repository** в верхней части окна.
3. В **Name** оставь `japan-travel`. Если такой репозиторий уже есть в аккаунте, выбери другое имя и учитывай его в адресе сайта.
4. Сними галочку **Keep this code private**, чтобы создать публичный репозиторий для бесплатного Pages.
5. Выбери личный аккаунт; организация не требуется.
6. Нажми **Publish repository** и дождись окончания загрузки, включая фотографии.
7. Выбери **Repository → View on GitHub**.

На странице репозитория в корне должны быть `index.html`, `brochure.html`, `.nojekyll`, папки `days`, `assets`, `tools` и документы. Ключевое условие: `index.html` находится сразу в корне, а не внутри дополнительной папки `japan-travel`. [Публикация через GitHub Desktop](https://docs.github.com/en/desktop/adding-and-cloning-repositories/adding-an-existing-project-to-github-using-github-desktop).

## 4. Включить GitHub Pages

1. На сайте GitHub открой свой репозиторий `japan-travel`.
2. В верхнем меню репозитория открой **Settings**.
3. Слева выбери **Pages**.
4. В разделе **Build and deployment** установи:

| Поле | Значение |
|---|---|
| Source | Deploy from a branch |
| Branch | main, либо фактическое имя основной ветки |
| Folder | / (root) |

5. Нажми **Save**.
6. Поле **Custom domain** оставь пустым: бесплатный адрес `github.io` достаточен.
7. Дождись публикации. GitHub указывает, что изменения могут публиковаться до 10 минут.
8. Вернись в **Settings → Pages** и нажми **Visit site**, когда появится ссылка. Состояние публикации можно посмотреть во вкладке **Actions**.

Отдельный workflow создавать не требуется, хотя GitHub может показывать автоматически запущенную задачу `pages build and deployment` во вкладке Actions. [Настройка источника публикации](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

## 5. Адрес и проверка сайта

Если логин GitHub — `YOUR-LOGIN`, а репозиторий — `japan-travel`, адрес сайта будет:

```text
https://YOUR-LOGIN.github.io/japan-travel/
```

Замени `YOUR-LOGIN` своим логином. Не нужно называть репозиторий `YOUR-LOGIN.github.io`: для этого проекта достаточно имени `japan-travel`.

Проверь главную, открытие обоих дней, фотографии, ссылку «Все дни», раскрытие истории и «Показать местному». Затем открой этот же адрес на iPhone и iPad. Общая брошюра доступна по адресу сайта с добавлением `brochure.html`.

## 6. Обновление после новых дней

1. Продолжай работать в той же папке `E:\japan-travel`.
2. Попроси помощника оформить новые дни по `NEW_DAY_PROMPT.md`. В инструкции уже предусмотрены обновление главной, брошюры, генератора и проверка результата.
3. После завершения открой GitHub Desktop и выбери репозиторий `japan-travel`.
4. Во вкладке **Changes** просмотри изменения. Для одного обновления сайта обычно нужно отправить вместе новые страницы, фотографии, главную и брошюру.
5. В **Summary** напиши, например, `Add days 3 and 4`.
6. Нажми **Commit to main**, затем **Push origin**.
7. Дождись успешной публикации и обнови сайт. Если приложение показывает **Fetch origin** и вкладка **Changes** пуста, проверь **History**: возможно, изменения уже отправлены.

**Commit** сохраняет версию на компьютере. **Push origin** отправляет её на GitHub. После отправки GitHub Pages обновляет сайт автоматически; настройки Pages повторять не нужно. [Сохранение и отправка изменений](https://docs.github.com/en/desktop/overview/creating-your-first-repository-using-github-desktop#part-5-making-committing-and-pushing-changes).

## 7. Если возникла проблема

| Проблема | Что проверить |
|---|---|
| Сайт возвращает 404 | Прошла ли первая публикация; выбран ли правильный Branch и `/ (root)`; находится ли `index.html` в корне; открыт ли полный адрес с `/japan-travel/`. |
| В Pages нет нужной ветки | Сначала выполни первое сохранение и Publish repository. Затем обнови страницу настроек. |
| Нет фотографий | Загружена ли папка `assets/photos`; сохранены ли имена файлов и регистр букв. В готовом проекте пути относительные. |
| Видна старая версия | Был ли выполнен Push origin после Commit; завершилась ли задача в Actions; обнови страницу или открой в приватной вкладке. |
| Главная открывается, новый день не появляется | Отправлены ли вместе обновлённый `index.html`, файл нового дня и его фотографии. |
| GitHub Desktop не видит изменения | Через Repository → Show in Explorer проверь, что подключена именно папка `E:\japan-travel`. |
| Публикация завершилась ошибкой | Открой Actions → последнюю задачу Pages и посмотри сообщение об ошибке. |

Для публикации достаточно файлов сайта. Рабочие инструкции и tools можно хранить в том же репозитории, чтобы сохранять весь проект; они не запускаются на сервере Pages.
