# STYLE GUIDE · Путеводитель «Япония, 11–31 мая 2027» · v2.7

## 1. Назначение и формат
- Поездка: 11–31 мая 2027, 21 день. Маршрут создаётся с нуля из расписаний пользователя.
- Задача — оформление готового расписания, без перепланирования и изменения порядка или указанного времени.
- Основные устройства — iPhone и iPad; публикация пользователем на GitHub Pages.
- Статический HTML и CSS, без внешних шрифтов, библиотек и фреймворков. Полноценный офлайн-режим не нужен.
- До 899 px: одна колонка, текст до 480 px по центру, поля 22 px, фото на всю доступную ширину.
- От 900 px: контейнер до 1100 px, поля 40 px; карточка в две колонки (краткая информация слева, история и списки справа), план в две колонки, плитки по 7 в ряд.
- Все фотографии, включая обложку: 4:3 до 900 px и 16:9 от 900 px, object-fit:cover. Одинаковые размеры отображения при одинаковой ширине экрана.
- Дни во время работы: days/day-XX.html. Секция дня обёрнута комментариями <!-- DAY-XX START --> и <!-- DAY-XX END -->.
- Главная — index.html, итоговая сборка — brochure.html: главная секция и все готовые дни подряд. Фотографии — assets/photos/.
- Одинаковый CSS во всех HTML. Утверждённый эталон — days/day-02.html со всеми последними правками; не менять без прямой просьбы пользователя. reference.html — его синхронизированная копия с путями для корня проекта. Прежний пример Киото больше не используется. Новые дни повторяют дизайн и порядок блоков эталона, с собственными текстами и фото.
- По решению v2.6 фотографии для новых дней предоставляет пользователь; самостоятельно их не искать. Страницы атрибуций и ссылок на них нет. Дизайн и CSS эталона сохраняются; день 2 и reference.html ради смены порядка получения фото не менять.

## 2. Навигация, ID и пути
- Главная секция: id="index"; день: id="day-02"; карточки: id="d02-s01", id="d02-s02" и далее.
- В сборке плитка ведёт на #day-XX; в отдельном index.html — на days/day-XX.html#day-XX.
- В отдельном дне возврат — ../index.html#index; в сборке — #index.
- Строка плана ведёт на #dXX-sYY. Вся строка кликабельна.
- В заголовке дня под обложкой, рядом с датой, и в конце дня — «← Все дни». На узком экране строка заголовка может переноситься. Переходов к соседним дням нет. Закреплённой панели нет.
- Навигация обычными ссылками; раскрытие через нативные details/summary, без JS.
- Пути к фото учитывают расположение файла: ../assets/photos/ из days/ и assets/photos/ из корня. При сборке пути пересчитываются.

## 3. Дизайн
Сохраняются палитра, шрифты, плашки, вертикальные японские надписи и общий характер образца. Общие изменения только после согласования.

:root{
  --paper:#F4EFE4;  --paper-2:#ECE4D3;
  --ink:#1E1E1E;    --ink-soft:#5F5A54;
  --accent:#B4442C; --navy:#26344D;
  --gold:#C49A4A;   --rule:#D8CFBD;
  --t-temple:#B4442C;   /* 卍 храм */
  --t-shrine:#D2562B;   /* ⛩ святилище */
  --t-culture:#26344D;  /* 🎭 культура, шоу, музей */
  --t-street:#C49A4A;   /* 🍢 рынок, улица, квартал */
  --t-nature:#5E7B5A;   /* 🌿 сад, парк, природа */
  --t-modern:#6B6F7A;   /* 🗼 современное, мемориал, вид */
  --serif: "NumSerif", Georgia, "Noto Serif", "PT Serif", serif;
  /* NumSerif — только цифры 0–9: @font-face с local() Cambria → Times New Roman →
     Noto Serif; у Georgia цифры старинные, поэтому цифры берём отсюда */
  --sans: -apple-system, "Segoe UI", Roboto, "Noto Sans", sans-serif;
  --jp: "Yu Mincho", "YuMincho", "Hiragino Mincho ProN", "MS Mincho", "Noto Serif JP", serif;
  --jp-sans: "Hiragino Sans", "Noto Sans JP", sans-serif;
}

- Основной текст: serif 17px, line-height:1.65, font-variant-numeric:lining-nums.
- Название места: serif курсив 40–44px, line-height:1.05.
- Анонс: serif курсив 20px, --ink-soft.
- Подписи: sans 12px, uppercase, letter-spacing:.14em, --accent.
- Японский текст — --jp, минчо. Под названием 26px, --accent.
- NumSerif: только цифры, локальные Cambria / Times New Roman / Noto Serif; начертания из reference.html.

## 4. Компоненты

### 4.1 Главная
- «ПУТЕВОДИТЕЛЬ», «Япония», 日本, «11–31 мая 2027», согласованный маршрут по городам через « → ».
- Все 21 плитка сразу: 3 в ряд, до 359 px — 2, от 900 px — 7.
- Плитка: номер дня, дата, день недели; город и японское название добавляются только после получения расписания.
- Готовый день — ссылка, фон --paper и рамка --ink. Неоформленный — без ссылки, opacity:.4, подпись «скоро».
- Цветная полоса города задаётся через --city. Цвет фиксируется в PROGRESS.md при появлении города в расписании. До этого — нейтральная --rule, без выдуманного города.

### 4.2 Обложка дня
Реальное фото города → строка «день, дата и день недели» со ссылкой «← Все дни» справа → город → японское название → анонс в 1–2 предложения. Пропорции фото такие же, как у остановок.

### 4.3 План дня
- Подпись «ПЛАН ДНЯ», заголовок «Маршрут по часам», короткий анонс.
- Время пользователя сохраняется. Если его нет — «утро», «днём», «вечер», без выдуманного точного времени. Если часть суток нельзя определить из расписания — уточнить.
- Время sans bold 20px --navy, часть суток --gold; название serif 22px, японский текст 16px, характеристика до 7 слов.
- Между строками линия --rule; у ссылок стрелка «›».
- Сбор, переезд, возвращение без карточки — строка без ссылки и стрелки; в число остановок не входит.
- Для дня дороги без экскурсионных остановок достаточно обложки, вступления, строк плана и возврата к плиткам, как в дне 1. Блоки карт, часов, фактов и истории не добавлять ради одинакового числа блоков.
- Опциональная остановка получает только отметку «Опционально». Объяснения, когда её пропускать, не добавляются.
- Длительность показывается только при наличии в расписании. Не рассчитывать и не подставлять её самостоятельно.

### 4.4 Фото и плашки
- У каждой остановки и обложки обязательно реальное фото именно этого места. Единые пропорции по разделу 1.
- Слева снизу плашка: --paper-2, рамка --rule, полоса 3px --accent, лёгкая тень; «ОСТАНОВКА N ИЗ M» и время/часть суток.
- Справа вертикальное японское название: writing-mode:vertical-rl, --jp, белое с тенью и при необходимости лёгким градиентом. Длинное название уменьшается по образцу.
- Слева сверху у опциональной остановки — «ОПЦИОНАЛЬНО».

### 4.5 Заголовок
Метка типа + «РАЙОН · ТИП» → русское название курсивом → японское название → краткий анонс → две кнопки.

### 4.6 Тип места
Один основной тип: 卍 ХРАМ, ⛩ СВЯТИЛИЩЕ, 🎭 КУЛЬТУРА, 🍢 УЛИЦА / РЫНОК, 🌿 САД / ПРИРОДА, 🗼 СОВРЕМЕННОЕ. Цвета по разделу 3, оформление по образцу.

### 4.7 «Открыть в Картах»
Контурная кнопка --navy, высота не менее 40px. Проверенная ссылка Google Maps на конкретное место, когда доступна; иначе проверенный поиск по точному названию и городу. URL, идентификаторы и координаты не выдумывать. Для новой вкладки rel="noopener". Кнопку официального сайта не добавлять.

### 4.8 «Показать местному»
- Нативный details, закрыт по умолчанию, summary выглядит как вторая кнопка.
- Внутри крупное японское название, чтение каной, латиница, город и проверенный японский адрес.
- Для большой территории указывается адрес конкретного входа/точки, только после проверки. Если корректный адрес подтвердить нельзя — уточнить, не придумывать.
- Кнопки не сдвигаются при раскрытии. Длинный адрес переносится в пределах экрана.

### 4.9 Полоса фактов
Необязательна: добавлять только если даёт новую информацию, а не повторяет анонс и «За 30 секунд». До трёх содержательных фактов, без заполнения ради количества. Стиль линий и подписей по образцу, число равных колонок соответствует числу фактов (grid-auto-flow:column).

### 4.10 «За 30 секунд»
Видимый блок с тремя краткими пунктами: «Что это», «Главное», «Не пропустите». До 15 слов на пункт. Формулировки конкретные; сомнительных деталей ради заполнения не добавлять.

### 4.11 «История и подробности»
- Нативный details class="story", закрыт по умолчанию, summary «История и подробности». Расположен после «Найдите на месте» и «На месте».
- Внутри: вступление с красной буквицей, тематические разделы, легенда при наличии, «История и даты», дополнительные факты.
- Начинать с того, что посетитель увидит и чем место интересно; затем объяснять историю.
- Для небольшого объекта достаточно короткого рассказа. Не требовать двух абзацев, заданного числа разделов, дат или фактов.
- Заголовки красной капителью с тонкой линией, как в образце.

### 4.12 Легенды, даты и факты
- Легенды отделены от истории и помечены «По преданию»; синий фон и золотая подпись по образцу. Если легенды нет — блок пропускается.
- «История и даты»: годы с событиями, вертикальная золотая линия; только содержательные даты, без обязательных 4–8 пунктов.
- Дополнительные факты — с красной полосой слева; не повторяют уже сказанное.
- Нет обязательной нормы слов, числа фактов и разделов.

### 4.13 «Найдите на месте»
Постоянно видимый обычный список: деталь и где искать. Верхний отступ от предыдущего блока — 32 px, в том числе когда список первый в колонке. Обычно 3–5 пунктов, для малого места допустимо меньше. Только существующие, доступные посетителям детали. Без чекбоксов, зачёркивания, JS и localStorage.

### 4.14 «На месте»
Постоянно видимый блок на фоне --paper-2: конкретные советы по осмотру и этикету. Подсказки пользователя включаются сюда или в «По пути». Рекомендованную длительность не придумывать; использовать только переданную пользователем.

### 4.15 Часы и стоимость
- Сразу после двух кнопок — компактная горизонтальная полоса из ровно трёх равных ячеек, визуально как полоса фактов.
- Ячейки строго в порядке: «Часы работы», «Стоимость», «Последний вход». Только короткая подпись и значение, без общего заголовка, фона-плашки, дополнительных строк и пояснений.
- Стоимость — только обычный взрослый билет в иенах. Детские, школьные и прочие категории не показывать.
- Примеры: «8:30–18:30», «¥2 180», «17:30»; для бесплатного места — «Бесплатно»; неизвестное значение — «Не указана»/«Не указаны», неприменимый последний вход — «—».
- Для открытых территорий не выдумывать часы: «Без расписания», для квартала с разными заведениями — «По заведениям».
- Каждый день заново проверять данные по официальным источникам. Даты проверки, выходные, расхождения источников и сведения о подтверждении на май 2027 хранить в PROGRESS.md.
- На странице не показывать дату проверки, подпись «Текущие сведения проверены» и предупреждающую плашку. Не дублировать убранные пояснения в советах.
### 4.16 Перемещение и «По пути»
- Переданные пользователем способ, длительность, станции и пересадки показывать отдельно от экскурсионного рассказа; недостающие детали не рассчитывать самостоятельно.
- Для перемещения — блок «Переезд → …» или «Переход → …» с тем же спокойным оформлением, что у .way.
- «По пути → …» — отдельный рассказ о том, что увидеть по дороге, если такой маршрут есть в расписании.
- Не добавлять остановки или обходы, меняющие готовое расписание.

### 4.17 Конец дня
«← Все дни». Нет секции и ссылки «Фотографии и лицензии», кнопок следующего/предыдущего дня, закреплённой панели и развёрнутого блока источников. Под фотографиями и внутри карточек подписи авторов не размещать.
- Нижняя ссылка находится в `.way.day-end`: без верхней линии, верхнего margin и padding. Правило `.way.day-end{margin-top:0;padding-top:0;border-top:0}` действует во всех отдельных днях и брошюре. Обычные блоки «Переезд» / «По пути» сохраняют свои линии и отступы.

### 4.18 Фотографии от пользователя
- Для каждого нового дня сначала сообщить список нужных фотографий: отдельно обложка с видом города/местности и по одному снимку каждого места, включая опциональные варианты. Для составного маршрута ясно указать, какой объект должен быть на снимке.
- В списке указывать названия мест и подходящий сюжет, без поиска фотобанков, авторов и ссылок на изображения. Не добавлять в маршрут места ради фотографии.
- Фотографии предоставляет пользователь файлами или конкретными ссылками. Можно загрузить предоставленный файл по его ссылке; самостоятельно подбирать другие фото или генерировать изображения нельзя.
- Если часть фотографий ещё не передана, перечислить недостающие и продолжать независимую подготовку текстов и проверку фактов. Не выдавать день за готовый и не активировать его плитку до получения всех фото; заглушки не использовать.
- Страницу photo-credits.html, секции и ссылки «Фотографии и лицензии» не создавать и не восстанавливать при сборке. Прежние записи о происхождении изображений в рабочем манифесте сохранять, на страницы их автоматически не выводить.
- Готовые фотографии дней 1–7 сохраняются. Замена — только по просьбе пользователя, предоставленными им снимками.

## 5. Порядок карточки
1. Фото, плашка времени, японская надпись, отметка опциональности.
2. Метка типа, район, русское и японское название, анонс.
3. Кнопки карт и «Показать местному».
4. Горизонтальная полоса: часы работы, стоимость взрослого билета, последний вход.
5. Полоса фактов, только когда нужна.
6. «За 30 секунд».
7. Видимый список «Найдите на месте».
8. Видимые советы «На месте».
9. Закрытый блок «История и подробности».
Между карточками — отдельно перемещение из расписания и рассказ «По пути», если предусмотрен.

## 6. Текст и проверка
- Подробный путеводитель без заданного количества слов. Если о месте мало интересного — короткая карточка.
- Спокойный, живой и точный рассказ без рекламных эпитетов «потрясающий», «жемчужина», «must see» и восклицаний.
- События и даты связывать с объяснением, что и почему изменилось.
- Японские термины кратко переводить; названия по Поливанову, единообразно через глоссарий PROGRESS.md.
- Повторяющиеся понятия кратко объяснять заново, чтобы каждая карточка читалась самостоятельно.
- Легенды и факты не смешивать; сомнительное не включать.
- Советы на «вы». Анонс обычно одно предложение; характеристика в плане до 7 слов.
- Учитывать май 2027 года, не обещать неподтверждённые сезонные события.
- Источники исторических и практических сведений остаются в PROGRESS.md, без блока источников в тексте брошюры. Порядок получения фотографий от пользователя — в разделе 4.18.

## 7. Фотографии
- Самостоятельно фотографии не искать, не подбирать в фотоколлекциях, не скачивать из самостоятельно найденных источников и не генерировать. Сначала передать пользователю список по разделу 4.18, затем использовать предоставленные им файлы или конкретные ссылки.
- У каждой остановки и обложки остаётся реальное фото именно этого места. Соседний объект, объект того же типа и заглушка не подходят. Фотографии эталона автоматически не переносить в другие дни.
- Сохранять предоставленные фотографии локально в assets/photos/. Проверять соответствие месту, резкость и детали при размере показа на iPad. Желательны оригиналы от 3000 px; сохранять около 3200 px по ширине при достаточном исходнике. Не увеличивать маленькие изображения и не кадрировать далёкий объект до потери деталей.
- Если предоставленный снимок не подходит по месту, качеству или кадрированию, объяснить конкретную проблему и запросить у пользователя замену; самостоятельно замену не искать.
- Оптимизировать размер и формат без заметной потери качества; карточки loading="lazy", обложка без lazy. Пропорции — 4:3 и 16:9 по разделу 1.
- При замене менять имя файла для исключения старого кеша. Не повторять один снимок дважды. Назначение и локальный путь учитывать в PROGRESS.md и рабочем tools/photo-manifest.json; сохранять переданные сведения об источнике, не выдумывая автора или лицензию.
- Страница и публичные блоки «Фотографии и лицензии» не используются. Существующие рабочие сведения о происхождении фото не удалять.

## 8. Доступность
- Минимальная зона нажатия 40px, читаемый контраст, тень/градиент на фото.
- Нативное раскрытие доступно касанием и клавиатурой, видимый фокус.
